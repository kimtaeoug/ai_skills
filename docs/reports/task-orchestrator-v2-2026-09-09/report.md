# task-orchestrator v2 구현·검증 보고서

검증일: 2026-09-09. 판정: **조정 가능한 opt-in 로컬 v2 코어 검증 통과. 네이티브 실서비스 연동 완료를 의미하지 않음.** 기존 v1의 300개 작업 환경 시작 지연은 기준 미달이다.

후속 예시 검증: [평균 함수 시나리오](../average-example-2026-09-09/report.md)에서 테스트 실패 후 개발 보완 루프가 terminal 상태 때문에 차단되는 결함을 발견했고, 이후 **동일 워크플로 실패→보완→재검증→보고 완료를 검증하여 수정했다.** 아래 수치·해시는 최초 검증 당시의 기록이며 최신 수정 결과는 링크된 후속 보고서를 따른다.

## 적용 결과

- 워크플로별 시간·재시도·회로 차단·토큰·비용·반복 기본값을 부분 override할 수 있다. 실행 이후 변경은 미정산 호출이 없는 HIL 경계에서 인증된 승인으로 적용하며 이전/새 값, 이유, 승인자, 정책 버전을 저장한다.
- HIL 응답 대기는 실행 시간에서 제외한다. 다른 노드가 실행 중이면 워크플로 전체 시계는 계속 흐른다. 도구 제한시간과 별도의 승인 유효기간은 멈추지 않는다.
- 정책 변경이 누적 사용량·시도·반복·실행 시간을 초기화하지 않는다. 사용량보다 낮게 한도를 변경하면 종료한다. 알 수 없는 사용량 차단, 기본 거부, 증거 필수는 해제할 수 없다.
- 필수 단계 스키마·실행 주체·엣지 조건·증거·승인을 검증하고, SQLite 트랜잭션으로 예약/상태/수행 증빙을 저장한다. 큰 산출물은 해시 기반 외부 파일 참조로 전달한다.
- Claude/Codex 스킬 진입점에 v1 기록 모드와 v2 통제 모드를 구분했다. 실제 네이티브 사용량 계측·호출 상한·승인자 인증 어댑터는 설치하지 않았다. 해당 기능이 없는 관리 실행은 `awaiting_data`이며 임의의 0 비용이나 승인 문자열로 통과시키지 않는다.

사용법과 값 변경 예시는 [사용자 가이드](../../skills/task-orchestrator.md), 전체 계약/API는 [runtime-v2 안내](../../../.claude/skills/task-orchestrator/references/runtime-v2.md)에 있다.

### HIL·안전 검증

- 실행 600초 후 HIL 7200초를 기다려도 전체 3600초 한도 중 실행 잔여 시간은 3000초다. 이 검사는 승인 유효기간을 미리 늘린 조건이며, 기본 승인 600초에서는 별도로 만료·거부된다.
- 독립 순방향 검사에서 누적 토큰 150/비용 800을 유지한 채 비용 상한을 500으로 변경하자 정책 버전 증가 후 예산 초과로 종료했다.
- 인증 어댑터 없음, 미계측 호출, 위조/변조 승인, 변경된 입력·산출물, 잘못된 타입, 누락된 필수 단계 스키마, 증거 없는 성공, unknown usage의 0 대체를 차단했다.
- 실패한 시도 이력을 보존하며 허용된 장애만 재시도한다. 인증 실패는 장애 재시도로 돌리지 않는다. 종료된 워크플로의 다른 진행 호출은 감독 루프에서 취소하며 불확실한 사용량은 예약으로 남긴다.
- 독립 리뷰의 7개 지적을 수정했다: 입력 동일성 guard, 누락 주 어댑터 우회, enum 검증, 품질 필드 검증, 승인 필드, 필수 단계 스키마, 승인 인증 증빙 재검증. 마지막 수정 범위 재리뷰는 승인/지적 0건이었다. 이는 전체 시스템에 대한 보안 인증이 아니다.

## 변경 파일과 단순화

- 코어: `scripts/runtime_policy.py`, `scripts/runtime_contracts.py`, `scripts/graph_runtime.py` (canonical task-orchestrator 하위).
- 검증: `tests/test-runtime-policy.py`, `tests/test-runtime-contracts.py`, `tests/test-graph-runtime.py`, `tests/probe-graph-runtime.py`.
- 문서: Claude/Codex task-orchestrator `SKILL.md`, `references/runtime-v2.md`, 사용자 가이드, HIL 명세와 구현 계획, 본 보고서.
- Python 표준 라이브러리·로컬 SQLite·해시 파일 저장소만 사용했다. 새 패키지, 클라우드 서비스, 글로벌 훅, 자동 v1 마이그레이션을 추가하지 않았다. 기존 v1 `task_state.py`는 변경하지 않았다. 다른 작업의 미커밋 파일은 보존했다.

Python 구문 검사, `git diff --check`, 문서 상대 링크와 두 스킬의 YAML 메타데이터를 확인했다. 기본 스킬 검사기는 PyYAML 부재로 실행할 수 없어 설치된 Ruby YAML 파서로 name/description/frontmatter를 확인했다. 이 대체 검사는 기본 검사기의 모든 규칙을 검증했다는 뜻은 아니다. 별도 프로젝트 lint/typecheck/build 파이프라인은 이번 Python 표준 라이브러리 변경에 실행하지 않았다.

## 남은 제한과 조정 시점

1. 실제 Claude/Codex 모델·도구 실행을 통제하려면 신뢰할 수 있는 계측/상한/취소 어댑터와 인간 인증 연결이 필요하다. 지금은 로컬 호스트 런타임과 테스트 어댑터만 검증했다. 실사용 연결 없이 네이티브 비용 통제가 완성됐다고 주장하지 않는다.
2. 같은 OS 계정의 신뢰된 호스트 코드가 경계다. 임의 Python에 대한 샌드박스가 아니며, 어댑터는 분리되어 살아남는 자식 프로세스를 만들면 안 된다. 외부 시스템의 정확히 한 번 처리나 물리적 전원 장애 내구성까지 보증하지 않는다.
3. 실제 조사→개발팀→브라우저 화면 테스트 전체 E2E, 유료 공급자 장애, 장시간 soak/CPU·메모리 포화는 수행하지 않았다. 이번 변경은 UI가 없으며 화면 증거 계약만 테스트했다.
4. v1 300개 작업 시작 병목은 남아 있다. 해당 규모의 실사용이 필요할 때 별도 최적화한다. v2 조회 수치로 v1 결함을 가리지 않는다.
5. 실사용에서 타임아웃·재시도·예산 이슈가 관측되면 실패 사유와 receipt/계측을 근거로 해당 워크플로 값만 HIL로 변경한다. 긴 사람 검토가 예상되면 실행 한도 대신 **별도의 승인 유효기간**을 사전에 조정한다.
